Release notes for version 4.6.0 of the Rhize application.

Highlights for this release include:
- The Rhize Portal now includes Composer, where authorized users can browse Enterprises as cards, open an Enterprise to see its Sites, and open an active Site in a Composer tab.
- Composer also includes a Resource Model workspace that opens when you select an active Site. You can browse and add equipment, equipment classes, material definitions and material classes, place them on a canvas, and connect them to show how material flows through your site.
- A new GraphQL `onEvent` resolver enables clients to subscribe to events from pre-configured AMQP sources.
- GraphQL mutations can now read values, compute new ones, and write records together in a single request that either fully commits or not at all. This lets you do things like issue the next lot number without risking duplicates or partial writes, and you can also preview a mutation as a dry run before committing it.

25 Nov 2026

## Changes by service

The following sections document the changes this release brings to each service.

### Admin

#### Added

- Properties that a person inherits from a personnel class can now be edited on the person record.
- The Rhize Portal now includes Composer where authorized users can browse Enterprises as cards, open an Enterprise to see its Sites, and open an active Site in a Composer tab.
- Composer also includes a Resource Model workspace that opens when you select an active Site. You can browse and add equipment, equipment classes, material definitions and material classes, place them on a canvas, and connect them to show how material flows through your site.

#### Changed

- When creating a new version of a Physical Asset Class, the Hierarchy Scope and Includes Properties Of fields can now be set and are saved with the new version. The version tab no longer shows values from the previous version, and the first version of a new class now displays correctly instead of leaving the panel blank.
- In Master Data, selecting a different entity while on the Properties tab now keeps you on Properties and shows that entity's properties. Previously the tab stayed highlighted but the General view was displayed, so you had to switch to General and back to see the properties.
- Hierarchy scope on instance versions, such as Person, can now be cleared after it has been set.
- Optional fields on a physical asset class can now be set when creating a new version in the admin UI.
- The Equipment Data Sources table now shows a cleaner empty state when it has no data.
- The Admin UI pages for Process Segment, Work Calendar, Operations Event Class, Connection Type, Node Type, Material Definition, Data Sources, and Hierarchy Scope now use a shared page structure for versioned master data. These pages now look and behave the same way, so working with versioned records is consistent across them.
- The Admin UI Equipment sidebar now loads and expands equipment that has its own children, so you can reach every level of the hierarchy.


#### Fixed

- The previous and next page buttons on tables now load the correct set of records. Previously the page indicator changed but the table kept showing the same data, which affected the Asset Mapping tab on Equipment and the Equipment Mapping tab on Physical Asset.
- Equipment classes now correctly inherit properties from a linked active equipment class that has properties defined.
- Editing or disabling a property that a class inherits through "Include properties of" no longer changes that property on the origin class.
- The Hierarchy Scope field on the General tab of a work calendar now shows a single clear button instead of two.
- The three-dot menu and Save as buttons in the value columns of the Environment Variables table now work as expected. Their positioning has also been tidied up so the table is easier to use.
- Equipment asset mappings can now be created and saved correctly. Previously, a success message appeared but the new mapping was missing after reloading the page, and the updated table's styling made the page difficult to use.
- The Add mapping button on the Physical Asset page now works, so equipment mappings can be created again.
- Disabled operations definition segment parameters now show the standard yellow disabled styling when 'See inactive' is on. The three-dot menu also shows the correct enable or disable option, so parameters can be switched back and forth reliably.
- The workflow editor now uses the same code editor in all live-debug panels, so editing behaves consistently. You can also cancel suspended debug sessions, and the Continue button no longer causes an error after you close a debug session.


### Agent

#### Added

- Services now honour the HTTPS_PROXY, HTTP_PROXY and NO_PROXY environment variables when connecting to your identity provider for sign-in and token validation.

### BaaS

#### Added

- A new configuration option lets you disable introspection on the BaaS GraphQL API. This helps you restrict schema discovery in environments where you don't want the API structure exposed.
- Services now honour the HTTPS_PROXY, HTTP_PROXY and NO_PROXY environment variables when connecting to your identity provider for sign-in and token validation.
- A new GraphQL onEvent resolver enables clients to subscribe to events from pre-configured AMQP sources.
- GraphQL mutations can now read values, compute new ones, and write records together in a single request that either fully commits or not at all. This lets you do things like issue the next lot number without risking duplicates or partial writes, and you can also preview a mutation as a dry run before committing it.

#### Changed

- Large indexed lists are now better protected against data loss during crashes, restores, and replica catch-up, so they stay readable after a failure. A new read-only audit tool also finds damaged lists so they can be repaired, and release builds now run the integrity checks that were previously available only in debug builds.

#### Fixed

- Rebuilding an index from the admin API now leaves the index readable by all queries, and no longer loses entries from commits made while a rebuild is running. An invalid start timestamp is now rejected, and a rebuild interrupted by the node, such as by a backup, is reported as failed.
- Applying a GraphQL schema after an upgrade no longer hangs or runs out of memory when many fields need their indexes rebuilt. Index rebuilds now run a limited number at a time, which you can configure, and the logs show progress for each rebuild.
- Backup export now reads group directory names correctly in clusters with 10 or more groups.

### Workflow

#### Added

- Services now honour the HTTPS_PROXY, HTTP_PROXY and NO_PROXY environment variables when connecting to your identity provider for sign-in and token validation.
- The token expiry margin is now configurable, so you can set how long before a token expires it is treated as expired. The default value of 30 seconds matches the existing hard coded margin.

#### Changed

- Timer-started workflows no longer run with an empty access token: if the token can't be retrieved, no workflows start on that tick and the next scheduled tick tries again. Timer-started workflows now run asynchronously on the same workflow engine as rule-started workflows, so a timer can start a new run while an earlier run of the same workflow is still in progress.

#### Fixed

- Replacing, deactivating or importing a timer-triggered workflow no longer affects other workflows that run on the same interval. Old versions of a workflow stop running once they are replaced, so they no longer fire alongside the new version or use up repeat counts.
- Timer-started BPMN workflows now fire at the UTC start time written in the cycle (for example R/2026-11-09T00:00:00Z/PT2M) and stay on schedule instead of drifting, and the first run is the next scheduled slot after activation rather than immediately. Date timer starts now work as one-off runs, and activating a version with a month or year interval or a date already in the past is rejected with an explanatory error.
- The workflow editor now uses the same code editor in all live-debug panels, so editing behaves consistently. You can also cancel suspended debug sessions, and the Continue button no longer causes an error after you close a debug session.
